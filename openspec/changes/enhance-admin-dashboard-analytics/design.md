## Context

The dashboard analytics (`#analytics` section of `public/admin.html`, lines 88–187) are 100% hand-rolled: no chart library — `admin.html` loads only `/js/admin.js` (line 562), and all charts are DOM + inline SVG generated by vanilla JS. Everything is computed client-side in `loadAnalytics()` (`public/js/admin.js:3233`) from raw list endpoints (`/api/auth/admin/registrations`, `/api/auth/admin/transactions`, `/api/auth/inventory`, plus users/pickups/announcements). The server-side `/api/auth/admin/analytics/*` endpoints exist but are NOT used by the dashboard.

Current renderers in `admin.js`: `renderLineChart` (1263, already draws an area + points), `renderHorizontalBarChart` (818, used by 4 panels), `renderPieChart` (972, used by Inventory Changes), `renderDonutChart` (913, exists, unused on dashboard), `renderSparkline` (1707, used by 2 stat cards), plus an empty-state helper `renderEmptyChart` (702) and a hover/focus tooltip layer (`bindChartInteraction` 778, `showChartDetails` 712, tooltip CSS `.chart-hover-tooltip` in admin.css ~1037). A global timeframe filter exists (`#analyticsTimeFilter`, admin.html 91–96; handler admin.js 3438) driving client-side bucket building (`buildAnalyticsBuckets` 1485).

Branding tokens in `admin.css` `:root` (5–96): navy `#1e3a8a`/`#152c69`, royal `#2563eb`, white, light blue `#eff6ff`, gold `#facc15`. Cards: white `--radius-2xl` 24px, `.chart-box` min-height 280px, `.charts-container` 2-col desktop (2225) → 1-col ≤768px (2232).

## Goals / Non-Goals

**Goals:**
- Replace each analytics panel with the chart type specified in the proposal/spec, keeping the card layout, sidebar, header, spacing, and blue/white/gold branding.
- Extend the existing vanilla renderers rather than introduce a chart library; add the missing chart types (ranked gradient bars, status bars, donut with center total + legend, timeline, forecast with confidence band) and KPI/sparkline upgrades.
- Keep all metrics computed client-side over existing endpoints; no backend changes.
- Enforce timeframe filtering, empty states, responsiveness, memoized datasets, lazy render of heavy charts, first-render-only animation, and accessibility (contrast, keyboard tooltips, aria labels, responsive legends).

**Non-Goals:**
- No new dependencies (no Chart.js on the dashboard page; the CDN is CSP-allowed but unnecessary for SVG charts).
- No backend/API changes; no schema or data-model changes.
- No changes to the sidebar, header, card layout, or overall page structure.
- No changes to other pages (requests-management.html already uses Chart.js; untouched).

## Decisions

### D1: Keep vanilla SVG/DOM renderers; no chart library
Extend `admin.js`'s existing renderers and add new ones (area, ranked gradient bars, status bars, donut w/ legend + center total, timeline, forecast w/ confidence band, KPI cards, sparklines). Chart.js would require persistent instances + destroy/recreate and doesn't provide a timeline primitive; the current stateless rebuild pattern fits memoized, filter-driven re-renders.
- **Why**: zero deps, CSP-safe, matches existing code, tiny render surface (6 panels + 2 sparklines + summary).
- **Alternative**: Chart.js from CDN (already CSP-allowed; precedent in requests-management.html) — rejected: adds instance lifecycle complexity, no timeline chart type, more bundle weight.

### D2: Single orchestrator `loadAnalytics()` + renderer registry
Keep `loadAnalytics()` (admin.js:3233) as the sole entry point: build datasets → set stat values → render each panel via a small map of panel-id → renderer fn → attach tooltips. Timeframe change handler (admin.js:3438) stays; it re-invokes `loadAnalytics()`.
- **Why**: matches current architecture; makes per-panel rendering, memoization, and lazy rendering trivial to bolt on.

### D3: Memoize datasets; lazy-render heavy panels; animate once
- Cache each dataset builder's output keyed by `timeframe` (e.g., `chartCache` map cleared only when raw data or timeframe changes); skip re-render when cached dataset is identical.
- Lazy render the forecast + timeline panels only when their container scrolls into view (`IntersectionObserver`), then render once.
- Animation: add a CSS class (e.g., `.chart-animate-in`) on first render per container only; subsequent re-renders skip the animation class.
- **Why**: spec performance requirements; the rebuild-on-every-filter pattern otherwise recomputes everything.

### D4: Data semantics per panel (client-side, existing sources)
- Items Given Out: `getInventoryUsageEntries` (1385) → `buildUsageSeriesForBuckets` (1555) → smooth area SVG (extend `renderLineChart` 1263 with stronger area fill `#eff6ff`, circular points, hover tooltips).
- Most Requested: `aggregateUsageEntries(entries, getLabel, limit=10)` (1563) with blue→gold gradient fill (CSS `linear-gradient(90deg,#2563eb,#facc15)` per `.bar-fill` precedent at admin.css 1109).
- Low Stock: `buildInventoryHealthEntries(limit=…)` (1600) sorted ascending by quantity; color class per status band — Critical `quantity <= floor(reorderLevel/2) || quantity === 0` → red, Warning `quantity <= reorderLevel` → yellow, else Safe → green; tooltip includes reorderLevel.
- Active Courses: `aggregateUsageEntries` by cohort label (existing `cohort` = course-year) → donut via `renderDonutChart` (913) + center total + interactive legend + percentage tooltips.
- Inventory Changes: `getInventoryTransactions` (1576) + `classifyInventoryTransaction` (1580) → timeline (new renderer) with icon/date/time/adminName/action/quantity; color map Added green, Updated blue, Adjusted orange, Deleted red.
- Upcoming Demand: `buildPlanningForecastEntries` (1630) + a small linear forecast (weeks ahead from weekly usage, e.g., `buildWeeklySeries` 1230) → smooth line + confidence band (two translucent polygons ± stdev).
- KPI cards: new `renderKpiCards(container, items)`; data from existing summary computations (units issued, top item, top cohort, stock coverage `formatStockCoverage` 1678, critical low stock, slow moving `countSlowMovingItems` 1663).
- Sparklines: extend `renderSparkline` to all six stat cards (add missing SVG slots in admin.html stat-card markup).

### D5: Empty states centralized
One `renderChartEmptyState(container, iconKey)` producing icon + "No data available" + "Data will appear once transactions are recorded." (replaces/augments `renderEmptyChart` 702). Every panel renderer calls it when its dataset is empty; timeline uses "No inventory changes recorded." per spec.

### D6: CSS additions in `admin.css`
Add: `.chart-animate-in`, area/forecast SVG classes, gradient/status bar variants (`.bar-fill--gradient`, `.bar-fill--critical|--warning|--safe`), `.timeline`, `.kpi-grid`/`.kpi-card`, `.stat-sparkline--lg`, donut center/legend refinements, empty-state styles, responsive overrides (2-col → 1-col ≤768px already exists; ensure no overflow). Reuse existing tokens (`--brand-900`, `--accent-500`, `--radius-2xl`, `--shadow-md`).

### D7: Accessibility on top of existing layer
Extend `bindChartInteraction` (778) so all chart elements are focusable (`tabindex="0"`, role/aria-label) and tooltips are keyboard-visible; give each chart container `role="img"` + `aria-label` summary; legend items clickable for donut with `aria-pressed`.

## Risks / Trade-offs

- [Browser-side computation stays heavy on year filter] → Memoized datasets + lazy render mitigate; datasets are small (≤200 tx, ≤300 pickups).
- [SVG renderers drift from "smooth curve" aesthetics] → Use `C`/`S` bezier path segments (existing `renderLineChart` already produces smooth paths; reuse pattern).
- [Timeline admin-name lookup] → Transactions already carry `adminName` (adminService decorates); fallback "System" when missing.
- [Donut legend interactivity complexity] → Keep legend toggling slices visually (opacity) + tooltip, not data removal, to avoid re-computation.
- [Regression risk in `loadAnalytics()` rewrite] → Keep all existing stat element ids; update only render calls; manual browser pass required before archive (tasks include it).

## Migration Plan

1. Add new CSS classes (D6) to `admin.css`.
2. Extend `admin.js`: dataset helpers (memoized), new renderers (area/ranked/status/donut/timeline/forecast/KPI/sparklines), empty-state helper, lazy render + animate-once hooks.
3. Update `admin.html` analytics markup: stat-card sparkline slots, chart containers unchanged ids, replace `#analyticsummary` with KPI container.
4. Rewire `loadAnalytics()` render calls to the new renderers + timeframe.
5. Automated checks: `node --check` on admin.js; grep for stale renderer calls; ensure no console errors by loading the page (manual).
6. Manual browser verification: all 8 chart types + KPI + sparklines at day/week/month/year, empty states (fresh DB), desktop/tablet/mobile, keyboard focus.
7. Rollback: revert `admin.js`/`admin.html`/`admin.css` hunks; renderers are additive — old call sites are the only risk.
