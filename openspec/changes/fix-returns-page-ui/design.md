## Context

`public/admin-returns.html` renders the admin Return Requests page. It uses the shared `sidebar-shell` sidebar and the `admin-header` header (dark blue gradient). The main content section is an `admin-section dashboard-panel` containing a `dashboard-panel-header` (eyebrow "Return Management", title "All Return Requests", copy/description) and a `#returnFilterContainer` into which the shared `SmartFilter` library (`public/js/admin-filters.js`, the "unify-admin-filters" workstream) injects the filter toolbar. Below that is the returns table (7 columns) inside `.table-responsive`.

Current problems:
- The header duplicates the page description: `header-subtitle` ("View and manage return requests...") repeats the same sentence that also appears as `dashboard-panel-copy` in the content section. On medium viewports the header content collides because many inline Tailwind classes (`flex-wrap`, `grid-cols-2`, `gap-3`) crowd Search/Bell/Clock/Profile/Logout together.
- The SmartFilter toolbar renders many controls (search input, Status, Item Category, Return Reason, Date, Time, Sort, Reset Filters, Export) that can overlap or wrap unevenly under the current `.filter-toolbar` spacing in `public/css/admin.css`.
- The table can squeeze columns or overflow at narrow widths.

The sidebar order/visibility (including the recently reordered nav) must be preserved exactly — this change only touches layout/positioning.

## Goals / Non-Goals

**Goals:**
- Remove the header subtitle only; keep the identical sentence in the content section
- Header layouts cleanly on the left (Welcome Admin + Return Requests) and right (Search, Notification, Date/time, Profile, Logout) with consistent spacing, no overlap, at desktop/tablet/mobile
- Filter toolbar renders with uniform gap/padding/height/width, wraps naturally into a second row when needed, never overlaps controls, and keeps Export clear of everything
- Table columns align with adequate column widths and horizontal scrolling on narrow viewports
- Entire page responsive with no horizontal page overflow

**Non-Goals:**
- No backend, DB, API, route, auth, or authorization changes
- No changes to `public/js/admin-returns.js`, `public/js/admin-filters.js`, or any filter/search/sort/export/action behavior
- No redesign of colors, typography, borders, icons, or the visual theme
- No reordering of sidebar items (must remain byte-identical from `reorder-admin-sidebar-nav`)

## Decisions

**D1. Header subtitle removal is HTML-level, header alignment is CSS-level.**
Remove the `<div class="header-subtitle">...` node from `admin-returns.html` (around line 225). Do not add a replacement. All other header controls stay. Header spacing/alignment is then handled with existing/refined `.admin-header` CSS (the header already uses a flex row with `justify-between` and two groups: `header-left` and `header-right` plus a clock/logout grid). 
*Rationale:* The header markup already separates "left title block" from "right controls"; deleting the subtitle fixes the duplication, and CSS spacing resolves collisions without touching DOM structure beyond the removal.
*Alternative considered:* Replacing the subtitle with CSS `display:none` — rejected because hidden markup would still affect flex layout.

**D2. Filter-toolbar fixes live in CSS only (`public/css/admin.css`).**
The filter bar is generated by SmartFilter with the shared `.filter-toolbar` / `.admin-page .filter-toolbar` rule groups (around lines 2813-3080 and 3142-3170). Fixes: enforce `width:100%`, `flex-wrap:wrap` (already present) with a tuned `gap`, uniform control min-width/height via the shared select/input/combobox rules, and allow the toolbar to wrap to a second row rather than shrinking controls. Let the last row align left; Export stays a normal toolbar control so it can never collide with the table.
*Rationale:* SmartFilter output is shared across pages (admin, inventory variants); scoping CSS to the returns container isn't necessary because the shared toolbar rules are consistent everywhere. Keep edits additive and scoped so other pages benefit equally and nothing regresses.
*Alternative considered:* Editing `admin-filters.js` to change layout — rejected (changes shared behavior and violates the do-not-touch-JS constraint).

**D3. Table uses existing `.table-responsive` scroll container.**
Keep `.table-responsive` (already in the HTML) and ensure it has `overflow-x:auto` so the 7-column table scrolls horizontally below the container min-width rather than squeezing columns. Add min-widths to the Actions/Items columns for legibility. 
*Rationale:* Minimal change; the wrapper already exists, proving horizontal scroll instead of column crushing.

**D4. Responsive tiers reuse the current Tailwind breakpoints (md/lg) + existing media queries.**
Add/refine media queries in `admin.css` for header and toolbar at tablet and mobile widths (already partially present in the `unify-admin-filters` blocks). The page already uses the responsive sidebar (off-canvas + `mobileMenuBtn` on small screens), which must not be altered.

## Risks / Trade-offs

- [Shared `.filter-toolbar` CSS changes may affect other pages (inventory, feedback, requests)] → Keep changes additive and visually conservative (gap/min-width/wrap only); spot-check inventory and feedback pages after implementation.
- [Header tweaks might shift layout on other admin pages that reuse `.admin-header`] → Scope header fixes to classes/containers already unique to this page where possible (e.g., the subtitle removal is page-local), and verify sibling pages render the same.
- [Horizontal table scroll on mobile could hide the Actions column] → Add `min-width` to the Actions column and keep it as the last scrollable column, consistent with existing patterns.
- [CSS-only filter fixes could be overridden by inline Tailwind utility classes on generated controls] → Refine the specificity of toolbar rules to match existing patterns used by `unify-admin-filters` so changes apply.

## Open Questions

- None blocking implementation priority; filter toolbar controls are fixed by the shared configuration in `admin-returns.js` (Status, Item Category, Return Reason, Date/time, Sort, Search, Reset, Export), so the layout can target the generated `.filter-toolbar` structure directly.
